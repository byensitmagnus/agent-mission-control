## Decision and learning

The measured problem was added coordination without a reliable task-quality gain.
In the large audit a04 used 727,705 input tokens versus 367,442 for the existing
approach; the existing approach found at least as much. In direct, recovery and
optimization cases AMC bodies were not loaded, so outcomes cannot establish an
AMC execution benefit. Authentication no longer explains the result.

The architectural diagnosis is a supported hypothesis: broad activation and local
execution procedures competed with existing Context Diamond/AVO ownership. The
previous two-line composition repair did not reliably activate its intended owner.
This candidate makes ownership the entry point and narrows discovery instead of
adding another execution procedure. This is a clearer design, not causal proof of
better engineering or actual lower total context.

## Resulting architecture and changes

The lead owns architecture, constraints, integration and final acceptance. AMC
keeps cross-phase state and reconciliation. Applicable delegation/optimization
skills own their respective procedures; local fallbacks load only when a relevant
companion is unavailable. Optimization may delegate bounded jobs without losing
candidate selection. A failed companion cannot evade gates by switching fallback.

Small edits and understood dependency chains stay direct. Existing trackers and
adequate current independent review are reused; lead inspection and relevant
executed acceptance checks remain required. Missing proof is still NOT VERIFIED.
Risk/data/rollback gates and live-worker reconciliation remain intact. Offline
learning is separate from installed runtime authority.

The fallback instructions were shortened and tied explicitly to missing companions.
Optimization fallback now keeps the incumbent on ties, consistent with strict
improvement. UI discovery text and README match the narrower role. The optional
Codex example uses Astra lead and Luna for all four bounded roles, normally 1–2
children within its existing ceiling of 3. Uncertainty returns to the lead; no
nested agents or automatic stronger-child escalation. Core instructions remain
modelagnostic. No installed profile or global skill was changed.
