## Definition of Done and hard gates

1. Portable, decision-oriented core; optional documented Codex profile; no
   companion-skill dependency, daemon, database or added runtime dependency.
2. Exact Context and Evidence Packet fields, versioned root-owned Mission View,
   exclusive writer ownership, verified resume and autonomous repair loop.
3. Nine realistic cases with fixed rubric and disposable fixtures. Behavioral
   PASS requires observed isolated runs; unavailable runs stay NOT VERIFIED.
4. Standard-library structural validation covers metadata, local assets/links,
   TOML/config, packet/mission contracts, cases, SVG and unfinished placeholders;
   a negative fixture must fail. Root reruns checks independently.
5. Accurate installation/security/proof claims, preserved visual identity,
   no overwrite of user configuration. Independent final read-only review with
   no unresolved material findings, then one local commit and clean worktree.

No unsupported model/plugin claim may be presented as verified. Research may
require a clearly marked unavailable profile capability rather than fabricated
configuration. No credentials, GitHub settings changes or external mutations.
Evaluator and authorization are root-owned and cannot be relaxed by workers.

## Fixed decision order

Hard gates → completed realistic cases → scope/safety violations → necessary
user intervention → evidence completeness → measured time/tokens. No aggregate
score. Unobserved quantities are NOT MEASURED. Static validation is never a
behavioral eval. A capability unavailable in this environment is NOT VERIFIED,
not a failed product experiment and not a pass.

For comparisons use identical prompts, fixtures, model/reasoning, tools and
permissions, fresh isolated runs, and an evaluator separate from implementation.
Freeze the nine-case rubric before candidate code or instruction changes.
